# QuantumSafe Sentinel - Comprehensive Project Overview

QuantumSafe Sentinel is an advanced, end-to-end post-quantum cryptography (PQC) assessment, migration, and compliance platform. It bridges the gap between deep cryptographic analysis and executive-level business risk management. By automating the discovery of quantum-vulnerable cryptography and projecting migration impacts, it allows organizations to proactively prepare for "Y2Q" (Years to Quantum).

---

## Implementation Status (Recent Updates)
The project features newly implemented backend modules including:
- **PQC Benchmark Engine**: Uses `liboqs-python` to test Kyber768 vs RSA-2048, ML-DSA-65 vs ECDSA-P256, and X25519 (ECDH) hybrid schemas, reporting live performance and key sizes.
- **Automated PQC Remediation (Auto-Fix)**: Generates deterministic hybrid PQC patches using `liboqs` and autonomously submits GitHub Pull Requests using the GitHub REST API.
- **Accuracy Harness**: Validated to a 100% F1 accuracy score across a robust 41-sample corpus featuring intentional crypto-alias traps and non-cryptographic false-positive triggers.
- **Threat Horizon Sensitivity Analysis**: Interactive visualization of Mosca's Risk Inequality ($X + Y > Z$), dynamically recalculating risk globally.
- **Empirical Quantum Validation**: Dynamically generates generic Shor's algorithm circuits via Qiskit/qBraid for small targets (N=15, 21, 35) to empirically prove theoretical resource extrapolation models (e.g., $3n$ logical qubits) using measured physical/logical depths and qubits.
- **Migration Impact Estimator**: Calculates scalability metrics such as added bandwidth and storage overhead when transitioning to PQC algorithms.
- **Attack Theater Presentation Mode**: A dedicated, full-screen orchestration mode (`AttackTheater.tsx`) that stitches together live scanning, Mosca calculation, and automated PR remediation into a seamless, interactive narrative for audiences.
- **Presenter Control Panel**: A hidden reliability layer for presentation mode that monitors live dependency health (TLS scanner, GitHub API) and allows instantaneous fallback to cached data or scene skipping during live demos.
- **Visual PR Diffing**: Retrieves and renders real unified diffs from GitHub directly within the app (`AutoFixDiffViewer.tsx`), allowing audiences to verify the exact before/after cryptographic patches generated by the auto-fix engine.
- **Enhanced Live Certificate Scanner**: Extracts the full X.509 certificate chain (leaf, intermediate, root) directly from live TLS handshakes, correctly separating actionable leaf findings from informational intermediate CAs, and explicitly exposing Common Name (CN) details to prove real-time uniqueness.

## 1. Core Features & Capabilities

### Comprehensive Discovery & Scanning
- **Static Code Analysis (AST):** Uses robust AST parsing of Python codebases to identify hardcoded cryptographic primitives and library calls, surviving complex aliased imports (e.g., `import rsa as r`).
- **Certificate Scanning:** Analyzes X.509 certificates (`.pem`, `.crt`, `.der`) to identify vulnerable key exchange and signing algorithms, parsing extensions for usage contexts.
- **Configuration Analysis:** Uses regex to scan infrastructure configurations (nginx, Apache, SSH) for vulnerable cipher suites (e.g., ECDHE, DHE).
- **Live Endpoint Probing:** Performs active TLS handshakes against live domains to inspect the complete certificate chain in real-time, tagging chain positions (leaf vs root) and extracting Subject/Issuer context to demonstrate unique, real-time data capture.

### Advanced Risk Classification & Assessment
- **Mosca's Theorem Engine:** Calculates the "Harvest Now, Decrypt Later" risk window. It compares the time data must remain secure (`X`) plus the time to migrate systems (`Y`) against the estimated time until a Cryptographically Relevant Quantum Computer (CRQC) is built (`Z`).
- **Regulatory Compliance Mapping:** Maps discovered vulnerabilities to specific compliance frameworks (e.g., PCI-DSS v4.0, HIPAA, NIST SP 800-208, CNSA 2.0), providing clear deadlines and exposure summaries.
- **Executive Synthesis:** Automatically translates raw technical findings into a business-risk narrative (e.g., "CRITICAL: 5 assets have an active Harvest-Now-Decrypt-Later exposure window"). It generates prioritized, plain-English action items.

### Migration Planning & Impact Estimation
- **LibOQS Benchmarking Integration:** Leverages `liboqs` to benchmark PQC algorithms (like ML-KEM and ML-DSA) against classical ones (RSA, ECC).
- **Impact Projections:** Estimates real-world migration friction, projecting additional storage bloat (MB/day), bandwidth increases (%), and TLS handshake latency overhead (ms) caused by larger PQC keys and signatures.
- **Hybrid Recommendations:** Recommends specific, NIST-approved PQC replacements (e.g., Kyber-768, Dilithium3) and dictates when Hybrid (Classical + PQC) schemes are necessary for compliance and fallback security.

### Reporting & CI/CD Integration
- **PDF Reporting:** Generates polished, executive-ready PDF reports from scan results using `WeasyPrint` and `Jinja2`.
- **CBOM Exporting:** Exports Cryptographic Bill of Materials (CBOM) in standardized JSON format for compliance auditing and supply chain tracking.
- **CI/CD GitHub Action:** Packages the scanning engine into a lightweight CLI and GitHub composite action. This enables teams to gate pull requests automatically based on their quantum risk profile.

### Persistence & Trend Tracking
- **Local SQLite DB:** Automatically saves all scan results locally.
- **Migration Trending:** Tracks repeat scans of the same target over time, visualizing the reduction of critical findings and the improvement of the overall risk score.

## 2. Architecture & Technology Stack

The project is structured as a decoupled modern web application, split into a React frontend and a FastAPI backend.

### Frontend Architecture
- **Framework:** React 18, TypeScript, Vite.
- **Styling:** Tailwind CSS, `lucide-react` for iconography.
- **Visualizations:** `recharts` for rendering benchmark comparisons and historical risk trends.
- **Key Components:**
  - `ExecutiveSummary.tsx`: The primary dashboard. Displays the synthesized executive narrative, grading, migration impact, and regulatory exposure.
  - `InputPanel.tsx`: Handles file uploads (drag-and-drop) and live TLS probing inputs, orchestrating backend API calls.
  - `RiskTrendChart.tsx`: A line chart visualizing historical migration progress.
  - `MoscaTimeline.tsx`: A visual timeline explicitly rendering the math behind Mosca's Theorem (X + Y > Z).
  - `BenchmarkChart.tsx`: A bar chart comparing classical vs. PQC performance characteristics (Keygen, Encapsulation, Decapsulation).
  - `AttackTheater.tsx` & `PresenterControlPanel.tsx`: The primary presentation engine and its hidden reliability dashboard, ensuring seamless live narrative demonstrations.
  - `AutoFixDiffViewer.tsx`: Displays unified GitHub pull request diffs directly in the application.
  - `EmpiricalValidationChart.tsx`: Visually charts theoretical vs. measured hardware resources (qubits and depth) for breaking small prime modules (N=15, 21, 35) to validate extrapolation models.

### Backend Architecture
- **Framework:** Python 3.11+, FastAPI (async endpoints).
- **Cryptographic Libraries:** `cryptography` (X.509 parsing, primitive mapping), `liboqs-python` (PQC benchmarking).
- **Data Modeling:** Pydantic (strict schema validation for all inputs, outputs, and internal representations).
- **Storage:** SQLite (`sqlite3`) for zero-configuration, session-persistent historical data.
- **Exporting:** `WeasyPrint` and `Jinja2` (HTML to PDF rendering).

#### Backend Module Breakdown
- `api/main.py`: Central router, orchestrates the entire scan pipeline (scan -> classify -> map -> recommend -> impact -> synthesize -> save -> return).
- `detection/`: Contains the specialized scanners (`code_scanner.py`, `cert_scanner.py`, `config_scanner.py`, `live_scanner.py`).
- `classification/`: 
  - `risk_classifier.py`: Assigns baseline severity (Low, Medium, High, Critical).
  - `mosca_calculator.py`: Executes the theorem logic, now enriched with IBM Quantum Roadmap milestones for grounded Z-horizon estimates.
  - `compliance_mapper.py`: Cross-references algorithms with NIST/PCI matrices.
  - `executive_synthesizer.py`: NLP-style logic to construct the business narrative.
- `impact/`: `migration_estimator.py` models real-world overhead based on benchmark data.
- `recommendation/`: `recommender.py` maps vulnerable primitives to NIST standard replacements.
- `benchmarking/`: `liboqs_bench.py` executes live profiling of PQC algorithms.
- `quantum_demo/`: 
  - `shor_circuit.py`: Qiskit circuit simulation for Shor's algorithm (N=15).
  - `resource_estimator.py`: Estimates required logical and physical qubits for breaking RSA/ECC (citing published research).
- `export/`: `pdf_report.py` and `cbom_exporter.py`.
- `storage/`: `db.py` handles the SQLite abstraction layer.
- `cli/`: `scan_cli.py` is the lightweight standalone wrapper used by the CI/CD pipeline.

### CI/CD Architecture
- `.github/actions/quantumsafe-scan/action.yml`: A composite GitHub Action. It spins up a Python environment, installs minimal dependencies (`pydantic`, `cryptography`), runs the CLI against the PR's codebase, and posts a formatted Markdown comment summarizing the risk directly to the pull request. It fails the workflow if high-risk vulnerabilities are detected.

## 3. Data Flow Overview (Scan Lifecycle)

1. **Ingestion:** User uploads a ZIP file or enters a domain name in the React UI (or pushes a PR via GitHub Actions).
2. **Detection:** The appropriate scanner (AST, Regex, TLS Socket) analyzes the input and generates raw `Finding` objects.
3. **Enrichment:**
   - The Mosca Calculator attaches a margin of safety.
   - The Compliance Mapper attaches regulatory violations and deadlines.
   - The Risk Classifier determines the base severity.
4. **Recommendation:** The Recommender maps the finding to a PQC alternative.
5. **Impact Modeling:** The Estimator uses `liboqs` benchmark data to calculate how much overhead the recommended replacements will cause.
6. **Synthesis:** The Executive Synthesizer reads all enriched data and writes the plain-English narrative.
7. **Persistence:** The final `ScanResult` object is saved to `sentinel.db`.
8. **Presentation:** The frontend receives the JSON response and conditionally renders the Executive Summary, Benchmark Charts, and Trend Charts.

## 4. Quantum Theory Implementations

### Mosca's Theorem ($X + Y > Z$)
The application directly models Dr. Michele Mosca's theorem. 
- **X (Data Shelf Life):** How long data must remain secret (e.g., 50 years for health records).
- **Y (Migration Time):** The time required to replace existing infrastructure (e.g., 2-5 years).
- **Z (Threat Horizon):** The estimated time until a CRQC is available. 
  - **IBM Roadmap Integration:** The theorem calculator grounds the generic Z value by comparing the specific logical qubit requirement of a finding against IBM's public quantum roadmap milestones (e.g., Starling: 200 qubits by 2029; Blue Jay: 2,000 qubits by 2033), providing a specific, sourced timeline comment.
*If X + Y > Z, the organization is actively vulnerable to "Harvest Now, Decrypt Later" attacks.*

### Quantum Attack Cost (Resource Estimation)
The platform estimates the concrete quantum resources required to break detected classical cryptography:
- **RSA:** Projects logical and physical qubit counts based on published research (e.g., 20 million physical qubits / 8 hours for RSA-2048 per Gidney & Ekerå 2019, or <1M qubits / 177 days per Gidney 2025 refinement).
- **ECC:** Approximates resources required based on Shor-adapted ECDLP algorithms (citing Roetteler et al. 2017).
- **Hardware Gap Analysis:** Each estimate includes a plain-language comparison to today's largest physical quantum processors (e.g., IBM Condor ~1,121 qubits), calculating the exact multiplier required to reach the threat threshold.

### Shor's Algorithm Demo & Empirical Validation
The project contains an educational module (`quantum_demo/shor_circuit.py` and `qbraid_runner.py`) built with `qiskit` and `qBraid`. 
- **Empirical Validation**: It goes beyond a simple N=15 toy example. It dynamically generates and transpiles generic Shor circuits for N=15, 21, and 35. By executing them via qBraid QIR simulators (or local Aer fallback), it extracts the actual compiled circuit depth and measured qubit requirements, and compares them side-by-side against theoretical prediction models (e.g. $3n$ logical qubits), explicitly proving the mathematical foundation of the extrapolation models used to assess RSA-2048 risk.
